整页不再比窗口高
.ask-view 上的 flex: 1 会让浏览器忽略它自己那行 height，于是这一页按内容有多长就有多长，滚动的是整个窗口而不是中间的对话区，底部输入框被推到窗口下沿之外。改成 flex: none，并把硬写的 52px 换成 App.tsx 已经在实时测量的 --chrome-h。

卡片宽度固定填满栏宽
.brief-card 是 .flow 的 flex 子项，又带着 margin: 0 auto——交叉轴上的 auto 外边距会关掉 stretch，于是卡片按内容宽度收缩：同一栏里，方案文字长一点卡片就宽一点，短一点就窄一点，列宽会随着每次生成的结果轻微跳动。补一行 width: 100% 钉死。（正文换成输入框之后这个问题会放大，所以这条是必须的。）

交互：底栏留一行，四个键收成三个

原来是「确认，开始研究 C · 指令修订 I · 编辑 E · 放弃 Q」，四个键帽印在脸上。现在是「编辑  …  取消   开始」——左边是改这份方案，右边是处置这份方案。

「编辑」点开，底栏下面弹出一行，用大白话说要怎么改
不用先想清楚是「自己改字」还是「让模型改」——你只管说「多看早期的社区讨论」，剩下的它办。这一行默认收着，不占常驻空间；再点一次「编辑」或按 Esc 收回去。在右边点一下「编辑」试试。
4 → 3
「放弃」改叫「取消」，和「开始」并排在右下角
两个都是对这份方案的最终处置，放在一起、离左边的「编辑」远一点。「取消」是描边键、「开始」是实心键，轻重一眼分得开。有撤销 toast 兜底，不需要二次确认弹窗。点一下「取消」看看。
分清轻重
主键文案：「确认，开始研究」→「开始」
旁边已经有「取消」对照，「开始」不会有歧义；「确认」两个字描述的是点击这个动作本身，按钮该说的是点完会发生什么。档位和语言退回标题栏右上角。
−4 字
裸字母快捷键全部取消，「再按一次 C」跟着消失
原来只要焦点不在输入框，单敲一个 q 就把方案扔了；「再按一次 C 开始」这道防线，防的正是快捷键自己制造出来的风险——鼠标点按钮从来不会误触。换成 ⌘↩ 开始、Esc 取消（编辑行开着时 Esc 先收行）之后，那套「按两次」就没有存在理由了，一个用鼠标点出来的按钮也不必再教你用键盘。
去掉 1 处状态
键帽不常驻，按住 ⌘ / Ctrl 才淡入
快捷键留着——你是这个工具的主要用户——但它是熟练之后才该露出的东西。收起时键帽不是"透明"而是"没宽度"，所以按钮上不会留一块空白；按住修饰键时按钮平滑张开。在预览里按住 ⌘ 或 Ctrl 试试。
收回 4 个键帽
正文仍然可以直接点进去改，但不再挂按钮
研究范围常驻是一个自动撑高的输入框，只读时无边框无底色，鼠标划过透出一点底色，点进去才浮出框；改过之后标题旁挂「已修改 · 还原」。这是给想自己动手的人留的路，界面上不为它花任何位置——要不要留着这条路，你定（见下方说明）。
去掉 1 个按钮

已经定下来的两件事。
一、直接点正文改字这条路保留。研究范围常驻是一个自动撑高的输入框，只读时无边框无底色，鼠标划过透出底色，点进去浮出框，改完标题旁挂「已修改 · 还原」。界面上不为它花任何位置，只有 hover 底色和 tooltip 提示——「编辑」按钮仍然是唯一的明示入口，走的是自然语言那条路。
二、不做倒计时自动开跑。ChatGPT 那个「开始」键上的秒数环读完会自动执行；Prospector 起一次研究要烧几分钟 token，这张卡存在的理由就是让你核对完再点，所以不抄。

没有动的：配色、圆角、气泡、顶栏，以及澄清问答阶段的底部输入框（那个阶段它是要用的，照旧）。
