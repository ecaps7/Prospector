## 1. 目标与演示口径

**目标**：后续所有里程碑都在「可恢复、可观测」的地基上开发，而不是先写业务再补基建。

**演示口径**（路线图 §1）：

> 启动一个空流程 job → 中途 kill 进程 → 重启 → 从 checkpoint 续跑；日志自动关联 `trace_id` / `span_id`。

**为何不可延期**（设计 D7 / 排期原则 3）：研究任务 5–30 分钟；M1 起验证回路调试离不开断点续跑。后补 checkpointer 的典型风险是图状态已积累不可序列化对象。

- Redis / RabbitMQ / 三进程拆分（M4）

- 真实 LLM / Exa 调用；PageIndex
- 业务 `schemas/` 大部、`agents/`、`tools/`、`deterministic/` 业务逻辑
- FastAPI SSE、预算、质量门、评测跑批

M0–M3 运行时保持**单进程薄壳**；`flow/` 永不导入 `runtime/`。

## 3. 目录与模块边界（M0 切片）

路线图 §3 的完整树是终态愿景。M0 **只创建并充实**下表；其余目录可建空 `__init__.py` 占位，或等到首次有文件再加——二选一，团队选「需要 import 路径时再加」。

```
prospector/
├── pyproject.toml
├── .python-version                 # 3.13
├── .env.example                    # 非密钥默认值（preflight §7）
├── docker-compose.yml              # postgres + minio
├── migrations/                     # Alembic
│   ├── env.py
│   └── versions/
├── src/prospector/
│   ├── __init__.py
│   ├── config.py                   # 环境变量加载（无密钥写死）
│   ├── store/
│   │   ├── checkpoint.py           # LangGraph PG checkpointer 装配
│   │   └── object_store.py         # S3/MinIO 客户端薄封装
│   ├── flow/
│   │   ├── state.py                # 可序列化图状态（TypedDict / 等价）
│   │   └── research_graph.py       # M0：空/探针图；M1 起接真流水线
│   ├── obs/
│   │   ├── logging.py              # structlog 装配 + context 注入
│   │   └── tracing.py              # OTel TracerProvider / console exporter
│   └── runtime/
│       └── entrypoints/
│           └── local.py            # 单进程入口：跑空流程 / 恢复续跑
├── tests/
│   ├── unit/
│   │   └── test_m0_foundation.py      # 纯逻辑：config / key / 日志注入
│   └── integration/
│       └── test_m0_acceptance.py      # compose 验收：checkpoint / MinIO / 日志关联
└── .github/workflows/ci.yml
```

**依赖方向**（全程硬约束）：

```text
config / schemas(日后)
    ↑
store / obs
    ↑
flow
    ↑
runtime/entrypoints   ← 仅入口层知道「如何启动」
```

- `flow/` ↛ `runtime/`
- M0 尚无 `agents/` / `deterministic/`；不要为占位而引入循环依赖

## 5. 本地依赖：`docker compose`

### 5.1 服务

| 服务 | 镜像建议 | 用途 |
|------|----------|------|
| `postgres` | 官方 **PostgreSQL 18**（当前最新稳定主版本；镜像 `postgres:18-alpine`） | 事实库 + LangGraph checkpointer |
| `minio` | MinIO | S3 兼容对象存储 |

可选：`otel-collector`——**非必达**。默认用进程内 **console exporter** 满足验收。

### 5.2 初始化约定

- Compose 启动后，应用或迁移脚本须保证 schema `app`、`langgraph` 存在（可用 Alembic 前置 SQL，或 entrypoint init）。
- MinIO：创建桶（名来自 `S3_BUCKET`）；开发默认公开策略以简化本地，生产策略后移。
- `.env.example` 写入非密钥默认值（含 `DATABASE_URL`、`S3_*`）；密钥不入库。

### 5.3 应用连接

- `DATABASE_URL`：指向 compose 的 Postgres；search_path / schema 用法在 `config` 与 Alembic `env.py` 中写清（业务表 → `app`；checkpointer 表 → `langgraph`）。
- 对象存储：`S3_ENDPOINT` / `S3_ACCESS_KEY` / `S3_SECRET_KEY` / `S3_BUCKET`。

## 6. 数据库与迁移

### 6.1 Schema 隔离

| Schema | 所有者 | M0 内容 |
|--------|--------|---------|
| `langgraph` | LangGraph PG checkpointer | checkpointer 官方/库表结构（由 checkpointer setup 或迁移创建） |
| `app` | Prospector 业务 | M0 仅最小骨架（见下）；业务实体表从 M1 起 |

### 6.2 `app` 在 M0 的最小表

M0 不实现研究领域模型，但提供一个稳定的 **job 句柄** 以便演示「启动 / 恢复」并关联日志：

**`app.jobs`**

| 列 | 类型 | 说明 |
|----|------|------|
| `id` | UUID PK | job_id；`str(id)` 同时作为 LangGraph `thread_id` |
| `workspace_id` | UUID | 假租户常量 |
| `user_id` | UUID | 假租户常量 |
| `status` | text | `running` / `completed` / `failed` |
| `created_at` / `updated_at` | timestamptz UTC | |

**不做**：Evidence / Claim / Plan / usage / 业务事件表——留给对应里程碑。

### 6.3 Checkpointer 表

- 使用同步 `PostgresSaver` 与 psycopg 连接池；`setup_checkpointer()` 创建官方表结构。
- 表落在 `langgraph` schema，避免与 `app` 混名。

## 7. 空流程与 Checkpoint（主战役）

### 7.1 图状态（`flow/state.py`）

约束（D7）：**状态必须可序列化**（JSON/msgpack 友好）。禁止放入未注册的自定义类实例、打开的连接、线程锁、协程对象。

M0 探针状态：

```text
EmptyFlowState:
  job_id: str
  step: int          # 当前步序号
  notes: list[str]   # 每步追加一条短标记，便于断言续跑
```

### 7.2 空流程图（`flow/research_graph.py`）

不是业务图，而是 **checkpoint 探针**：

```mermaid
flowchart LR
  start[start] --> n1[step_a]
  n1 --> n2[step_b]
  n2 --> n3[step_c]
  n3 --> endNode[end]
```

- 每个节点：递增 `step`、append `notes`、打一条 structlog INFO（含 `job_id`）并创建短 OTel span。
- **故意可中断**：`step_b`（或中间节点）支持「睡眠 N 秒」或「等待标志文件」，便于 integration 在窗口内 kill。
- 编译图时注入 **Postgres checkpointer**；`thread_id` = job 的 thread 键。
- 验收入口：`tests/integration/_empty_flow_worker.py` 启动探针流程，`test_m0_acceptance.py` 在进程被 kill 后使用同一 `thread_id` 恢复。产品 CLI 不暴露空探针图命令。

### 7.3 `store/checkpoint.py`

职责单一：

1. 从 `DATABASE_URL` 构造同步 psycopg `ConnectionPool`，固定 `search_path=langgraph,public`。
2. 暴露 `get_checkpointer()`、`setup_checkpointer()` 与连接池生命周期。
3. **不**包含业务节点逻辑。

### 7.4 恢复语义（验收期望）

1. 创建 `jobs` 行，`status=running`；以该 job 的 thread 调用 `invoke` / `ainvoke`。
2. 进程在 `step_b` 执行中被 SIGKILL / 强制终止。
3. 新进程用同一 `thread_id` 恢复；已完成的 `step_a` **不重跑**；从中断点继续到 `end`。
4. 最终 `notes` 完整、`status=completed`；checkpoint 行存在于 `langgraph` schema。

## 8. 观测（`obs/`）

对齐设计 §9.1.4，但 **M0 只落地能力与契约**，不要求 Tempo↔Loki。

### 8.1 structlog

- 仅 stdout/stderr 输出 **JSON**；容器内不写日志文件。
- Processor 从 OTel / contextvars **自动注入**：至少 `trace_id`、`span_id`；有则注入 `job_id`（M0 探针图应设置）。
- 字段契约（存在则填）：`timestamp`、`level`、`service`、`event`、`message`。
- 内容最小化（§9.1.5）：默认日志禁止密钥、连接串、研究正文；M0 空流程本身无正文，但仍禁止把 `DATABASE_URL` 等打进日志。

### 8.2 OpenTelemetry

- 初始化 `TracerProvider`；默认 **ConsoleSpanExporter**（或 OTLP→可选 Collector）。
- 空流程入口创建一个 root span（如 `empty_flow.run`）；节点可用子 span。
- **故障隔离**：exporter / exporter 失败不得阻断 checkpoint 提交或进程正常退出（有界缓冲 / 吞掉导出错误）。
- 不在应用内引入第二套 tracing SDK（LangSmith 仅经 Collector 复制——M0 不做）。

### 8.3 M0 验收尺度

- 跑空流程时，同一执行的 JSON 日志中能读到非空的 `trace_id` / `span_id`，且与当前 span 一致。
- **不要求** Grafana 看板、Tempo 持久化、跨服务 link 链（后者属 M1 与 M4）。

---

## 9. 对象存储（`store/object_store.py`）

### 9.1 职责

- 基于 `boto3` 的 S3 兼容 API 提供 `put_bytes`、`get_bytes` 与 `exists`。
- Key 约定预留 Workspace 前缀（设计 §10）：例如 `{workspace_id}/…`；M0 冒烟可用 `m0/smoke/{uuid}`。
- 返回或记录 `storage_ref`（bucket + key），不把大对象塞进 Postgres。

### 9.2 M0 验收

- Integration：写入随机字节 → 读回一致。
- **不**实现 Document 快照业务（M1）。

## 11. 测试与 CI

### 11.1 分层

| 层 | 内容 | 依赖 |
|----|------|------|
| Unit | key 拼接、config 解析、状态序列化往返等 | 无 Docker |
| Integration | checkpoint kill/resume；日志含 trace；MinIO roundtrip | compose：PG + MinIO |

外部 LLM / Exa：**一律 mock**（M0 甚至无调用点）。

### 11.2 主验收用例伪步骤（`test_checkpoint_resume`）

1. compose up 健康检查。
2. 跑迁移 + checkpointer setup。
3. 后台启动空流程（中间节点长 sleep）。
4. 确认已越过 `step_a`（查 checkpoint 或日志）。
5. kill 进程。
6. 同 `thread_id` 恢复；断言最终状态与 `notes`；断言 `step_a` 副作用未重复（可用计数器节点或 notes 无重复标记）。

### 11.3 GitHub Actions 门禁

强制（preflight §2）：

1. `ruff check`
2. `ruff format --check`
3. basedpyright
4. unit
5. compose integration

## 15. 已落地实现选择

1. LangGraph checkpointer 使用同步 `PostgresSaver`。
2. S3 兼容对象存储客户端使用 `boto3`。
3. checkpoint kill/resume 集成测试使用文件屏障控制可杀窗口。
4. 根目录不保留 `main.py`，入口统一由 `pyproject.toml` 指向 `runtime.entrypoints.local`。
